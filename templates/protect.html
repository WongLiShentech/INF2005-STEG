Hide a signed verification record and a secret message inside a picture. The result looks identical to the original.

1. Cover object — the file you hide things inside

Pick a PNG, a WAV or a video, for example testFiles/original/cover.png, testFiles/original/cover.wav or testFiles/original/cover.avi. This is the container, not the secret. A protected image is always written as PNG, a protected sound as WAV and a protected video as AVI (FFV1, lossless), because lossy compression destroys the hidden bits.

2. Hiding password — decides where in the picture the data goes

Invent any password and share it with whoever needs to check the file. The hiding place is calculated from it and never stored anywhere, so a different password means a different spot. This is separate from the RSA signing keys in keys/, which decide who signed rather than where it is hidden. Its formal name is the start-location derivation key.

3. Start location — optional

Left blank, the hiding place is calculated from your password and can land anywhere in the first half of the file. Type a number instead and the payload begins exactly there, anywhere in the file. Whoever verifies must then be told that number as well as the password. Deriving it is the stronger choice: a number a person picks is usually round and near the start, which is exactly where someone searching would look first.

4. LSB depth — how many bits per colour value to overwrite

Depth 1 of 8 Capacity — Start offset —

Choose a cover object and type a key, and the capacity and start offset will appear here. Depth 1 or 2 is invisible to the eye; every extra bit doubles capacity and adds visible damage.

5. Secret message — what you actually want to hide

0 bytes typed. This is stored alongside a signed record identifying the file, so both can be checked later.

Leave this off and the message sits in the picture as readable text: anyone who finds the hiding place can read it. Turn it on and finding the hiding place is not enough, because the bytes are ciphertext. The cipher key is derived from the same password as the hiding place, but through a separate derivation, so the two jobs never share one secret. Adds 28 bytes of nonce and authentication tag.
